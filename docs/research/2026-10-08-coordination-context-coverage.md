# 独立协调上下文覆盖调研

日期：2026-10-08。阶段 32，先记录问题与取舍，再实现和验证。

## 当前证据

readSnapshot 默认只保留每份文档前 20,000 字符；buildCoordinationPrompt 按固定文档顺序消费剩余总预算。完整 hash 会随末尾变更更新，但模型可能始终看不到新的末尾验收要求；长 PRD、计划和 ADR 也可能挤掉 findings 或自定义产物。现有预算测试只检查长度和输入 hash，没有检查实际可见材料。

## 外部参考

通过 Firecrawl 读取 [Anthropic：Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)。文中将上下文视为有限注意力预算，主张提供足够的高信号材料与明确定位符，并用 head/tail、按需检索和渐进披露控制内容量。该资料支持显式选择材料的原则，不证明任何特定截断比例或分配策略最优。

## 本仓库取舍

独立协调只产一次 Draft，当前禁止工具读取全文；因此先让宿主按确定性规则覆盖每份文档的开头与结尾，并均分剩余字符预算，短文档用不完的份额回流。输出原文字符范围及省略数，模型不能把省略内容当作已核验。完整原文 hash 继续负责新鲜度，片段策略版本加入协调输入身份，旧策略轮次仍可审计但须重新协调。

不引入自动摘要或付费压缩调用，避免摘要成为第二份事实来源。首尾并不能保证捕获中间的关键要求；本轮明确披露这个边界，后续可在有实际检索需求时扩展受控取片段协议。普通 worker 的默认快照行为保留。

## 验证计划

先复现长 PRD 尾部丢失与后续报告饥饿，再验证首尾覆盖、均衡预算、字符范围可还原、完整 hash 与在途变更恢复、ACP 新会话跨重启以及无工作流副作用。最终执行完整离线测试、构建、类型和差异检查，并在隔离工作区做真实协调调用。

## 验收结果

4 个反例先全部复现。实现后 100 项定向与全量 713 测试 / 57 文件通过，build:all/typecheck/diff 检查通过；包括字符范围还原、UTF-16 代理对、短文档额度回流、非法预算拒绝、在途尾部变化恢复、ACP 重启后新会话与旧策略历史轮次迁移。

隔离 git 工作区内，PRD、计划、ADR、findings 和自定义评审报告均超过 60000 字符。实际 Claude architect 两轮调用均得到 ok/current 的 wait Draft，summary 准确引用 PRD/findings/自定义报告末尾的三个 A/B 标记；每轮 prompt=59950 字符，各文档纳入范围均对照原文校验，省略数明确大于 0。

server 重启后相同输入仍 current=true，更新尾部后旧轮次 current=false；新轮次 input hash 和实际会话 ID 不同。两轮均未调用工具，原文未改变，没有 worker 派发、人工决定或节点退出，待审审批 ID 不变，session doctor=true。运行数据、模型正文、抓取缓存只保留在临时目录。

该验收证明本机 CLI 能使用被提供的尾部材料，不证明统计意义上的模型质量或首尾策略能覆盖中间全部要求。原真实开发 Draft 另经实时 HTTP 核验仍有一个待审审批、零人工决定、done 未退出。
