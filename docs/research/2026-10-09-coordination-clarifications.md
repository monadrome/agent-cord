# 协调人工澄清闭环调研与验收

日期：2026-10-09。阶段 38。

## 当前缺口

CoordinationProposal 的 ask_human 提供问题与 2-6 个选项，但 console 只显示列表，REST 没有答复入口。用户不能形成可追溯回答，下一协调轮次和 worker 快照也没有该材料。把选项直接映射成 gate choice 会混淆需求澄清和人工审批。

## 外部参考

通过 Firecrawl 读取 [LangGraph JavaScript interrupts](https://docs.langchain.com/oss/javascript/langgraph/interrupts)，参考人工输入、持久化状态和显式 resume 的分离。agent-cord 继续采用最新快照和事实投影；答复不恢复模型私有历史、不替代现有 gate。

## 取舍与 UI

ADR-0052：仅选已有问题选项；答复引用原完成/input，当前有效才接受。完整事件事实投影到当前 workflow/revision，精确同题保留最新选择，坏引用与容量超限 fail-closed。没有答复时保留原输入身份，有答复时同批语义材料同时进入协调、worker 和审批上下文。

界面沿用已有蓝/红/绿状态、14px 正文、工具图标和未框定问题区；原生单选明确选择，“记录答复”带 Check 图标，保存中禁用操作，错误保留选择，过期禁用，完成展示选择与时间。不新增说明性卡片或自动启动命令。

## 验证计划

先复现答复路由缺失、下一快照缺材料、输入身份未变和 UI 不可选择。覆盖成功、过期/非法选项、并发一致/冲突、写失败恢复、冷重启不重放、scope 与坏引用、模型中途答复导致 stale、worker/审批读取，以及原 gate 不被放行。最后全量验证、隔离实际调用、浏览器桌面/手机和小步提交。

## 验收结果

14 个核心/REST 反例先复现，后续补齐原问题来源预写校验与替代完成时不写事实；替代完成反例先失败再修复。最终全量 846 测试 / 64 文件、build:all/typecheck/git diff --check 通过。覆盖原生 worker 收到选择、同题变化使 checkpoint 失效、审批身份变化、容量拒绝、损坏需求冷隔离和在途模型 stale。无澄清保留原语义身份。

隔离临时 git 工作区真实 HTTP 与 Playwright 模拟操作：失败请求不记录答复，选择保持；实际重试期间控件禁用，只形成一条答复；同选择重放、改选/过期拒绝，重启保留事实。答复前后 gate/节点退出/人工决定事实集合相同，worker 调用 0，人工待审 1，PRD 未变。模拟答复仅用于本临时需求，不是对原真实开发 Draft 的人工审批。
