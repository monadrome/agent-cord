# ADR-0041 ｜ 机器验证绑定声明的源码输入

- 状态：accepted（本地原型实现）
- 日期：2026-10-08
- 关联：ADR-0030（审批新鲜度）、ADR-0036（文件边界）、ADR-0040（机器验证证据）
- 来源：阶段 27 对验证输入身份的审查

## 背景

当前 verification input_hash 覆盖需求文档、账本、流程和 agent 配置，但不覆盖实际代码。代码改变而 PRD 不变时，旧通过结果仍可用于门禁和人工终审。

## 备选方案

- 仅使用 git HEAD：无法覆盖未提交的 Draft 和新增文件。
- 无条件扫描整个工作区：运行数据、依赖缓存和日志会让结果自行失效。
- 显式文件/目录输入范围：由发布流程声明验证对象，覆盖其中新增、删除和内容变化。

## 决策

`verification-passed.with.inputs` 可声明工作区相对文件或目录。server 对该节点所有验证检查的输入取并集，生成确定性的文件清单/字节内容/文件类型与权限摘要，再与既有审批上下文 hash 组合。

verification context 返回 source_inputs/source_hash；提交仍必须携带测试执行前取得的 input_hash，server 重算后才能落盘。事件保存 server 计算的 source_hash，不保存源码正文。后置 gate、人工审批消费和重启恢复使用同一个输入函数。

未声明 inputs 时保持 ADR-0040 的文档范围语义；声明为空或无法读取时 fail-closed。输入路径禁止越界、链接、硬链接、事实和管理路径；递归跳过依赖与构建目录。文件/总字节数和目录深度有上限，观察到扫描期间变动即拒绝该次快照。

重启时声明输入不可读，保留该 run 的等待事实并阻断派发，其他需求与健康接口仍可用；修复输入后可重新验证。最终人工 gate 应同时引用机器验证结果，避免前置机器 gate 通过后代码变化只生成新的人审提示而不要求重验。

## 理由

输入身份应标识测试实际针对的材料。目录清单参与 hash 能覆盖新增与删除；只保存摘要延续事件流不承载代码正文的边界；显式范围便于审查且不依赖 git 或特定测试工具。

## 被否方案

仅用 HEAD 不能证明当前 Draft；全工作区默认扫描不能区分源码与运行时产物。两者都无法作为当前本地原型的通用默认。

## 实现边界

范围由流程作者负责声明完整，不证明遗漏范围、OS/工具链或外部依赖相同；仍依赖受信宿主如实上报测试状态。便携文件 API 不提供跨进程文件树的原子事务，不替代隔离工作区或 CI 的固定检出。

## 证据来源

`readApprovalContextHash` 当前输入字段；阶段 18 未提交 Draft；阶段 26 宿主验证恢复链路及新增源码变更回归。
