# ADR-0007 ｜ 非对称模型分配：生成弱、判定强，且判定与生成必异构

- 状态：accepted（设计定稿，代码未实现）
- 日期：2026-09-24
- 关联：ADR-0006（盲评投票，判定侧异构的出处）、ADR-0013（投票执行器）、ADR-0016（agent schema 中的异构声明）
- 来源：方案提案 §6.6 agent 间协作标准化（非对称模型分配）；落实确认点 CP-32（已确认）、CP-23（待确认）；Q1 调研对「强编排 / 弱执行」生产系统反向案例的修正结论

## 背景

平台要在「实现类任务」与「验证/判定类任务」之间分配模型。两个经验事实把这个问题推到了设计层：

1. **弱模型在长任务里跑不通，根因不是「笨」**。实践观察到的失败集中在三处：认知超载（任务太大、约束太多）、不知道自己不知道（不知道自己缺什么信息）、犯错后无法自愈（陷入无效重试）。这三条都不是模型能力问题，而是**结构问题**——粒度、置信度标签、验证兜底可以兜住它们。
2. **判定侧的偏置是系统性的**。LLM 评委系统性偏爱自己模型的输出（self-preference bias，NeurIPS 2024 实证），人类评审认为等质的输出，模型会给自己人打高分。这意味着「判定 agent 与生成 agent 同构」时，投票/评审的独立性存在结构性缺陷，且缺陷方向一致（偏高）。

另有一个反向案例必须在设计时面对：**某头部厂商的生产级多 agent 系统采用的是相反方向的分配**——强模型做编排（拆解、汇总、判断），弱模型做执行（机械搜索、并行探索），实测效果显著优于单 agent。这说明不存在普适的分配公式，方向取决于「哪一步的认知负荷高」。本项目若照抄任一方，都会在另一类任务上出错。

## 备选方案

### 方案 A：同构对称分配（生成与判定使用同档、同家族模型）

- **是什么**：不区分生成与判定的模型档位，按任务重要性统一选模型；判定即「再跑一次」。
- **优点**：配置最简单；无模型矩阵管理成本；成本可预测；不需要维护异构约束的校验逻辑。
- **缺点**：判定与生成同源 → 共享盲区与先验，无法发现系统性错误；self-preference bias 直接生效，判定倾向给同族输出打高分；与 ADR-0006 的独立性保证正面冲突（独立性要求异构）。
- **后果**：投票会退化成「同一双眼睛看两遍」，而账本会把这些票记录为「独立一致」，产生虚假的可信度。

### 方案 B：统一使用最强模型（不分角色）

- **是什么**：所有角色（生成 + 判定）都用最高能力模型。
- **优点**：单点质量最高；无分配决策；不存在「弱模型返工」的隐形成本。
- **缺点**：成本随需求规模线性上升，而生成类任务占总调用量的绝对多数；更关键的是**错误相关性反而更高**——大规模实证表明模型越大越准，跨架构跨供应商的错误相关性反而更强，即「全用最强」并不能减小共享盲区，只是把成本放大。
- **结论**：质量提升有限、成本上升确定，方向错了。

### 方案 C：非对称分配（生成弱、判定强），判定与生成必异构

- **是什么**：实现类任务默认派给低成本模型；验证/判定类任务用高能力模型，且判定模型必须与生成模型异构（不同模型家族/供应商）。
- **优点**：
  - 成本结构最优：验证侧的自主性意味着可以接受高成本强模型，只要生成侧足够便宜；
  - 与「弱模型跑不通的根因是结构问题」吻合：用结构（细粒度、置信度标签、验证兜底）兜住生成侧，用强模型把住最后一关；
  - 判定与生成异构直接消除 self-preference bias，使判定结果可被采信；
  - 异构同时还提高了错误的相关性下限（虽然不能消除，见证据 10）。
- **缺点**：
  - 需要维护模型矩阵与异构约束的校验（哪个角色必须与谁异构），配置复杂度上升；
  - 成本假设（判定侧强模型成本 < 生成侧节省）需要实验数据验证，否则「省下来的钱花在判定上」可能不成立；
  - 方向并非普适：在「拆解难、执行机械」的任务上，方向应当反过来（见决策中的修正口径）。

## 决策

**采用方案 C，并附加一条修正口径。**

1. **非对称模型分配**：实现类任务默认派给低成本模型；验证/判定类任务用高能力模型。
2. **判定 agent 与生成 agent 必须异构**（CP-32 已确认）。依据是 self-preference bias 实证，成本影响小，属于低代价高收益的约束。
3. **修正口径（必须与第 1 条同时成立）**：模型分配的依据是**各角色在流程中的认知负荷**，而非固定的「生成弱 / 判定强」公式。生产级系统存在相反方向的分配（强编排 / 弱执行），其成立前提是「拆解与判断的认知负荷高于执行」；本方案的方向成立前提是「生成是机械执行、判定是难度所在」。当某条流程确实呈现前者形态时，允许按角色认知负荷反向配置。
4. **异构约束显式声明在 agent schema 中**（例如 `model: {tier: strong, heterogeneous_with: [generator]}`），由平台校验而不是靠约定；判定与生成同族时加载期报错。
5. **与外部已有能力显式区分**：若组织内已有「异构模型调度」类基础设施，本方案的异构约束是**协议层要求**（保证判定独立性可审计），不是调度实现；二者是层次关系，需在接入文档中写明，避免被理解为重复造轮子。

## 理由（第一性原理推导）

1. **从「生成侧失败的真实根因」反推**：如果弱模型的失败来自结构（认知超载、不知道自己不知道、无法自愈），那么解法就是结构而不是换模型——把任务粒度切到与依赖图自然对应的水平、给结论加置信度标签、为不可自愈的部分加验证兜底。结构补齐后，生成侧用便宜模型是成立的。
2. **从「验证侧的成本容忍度」反推**：验证调用次数远少于生成调用次数（一个决策点一次判定 vs 一个任务多轮生成），因此验证侧使用强模型的总成本可控；而验证侧的质量直接决定账本的可信度——账本错了，下游所有机制都在错误事实上运行。所以成本应该优先投在验证侧。这条推导同时给出了成本假设的边界条件：只有当生成侧的节省大于判定侧的增量时才成立，需实验校准（CP-23）。
3. **从「偏置的方向性」反推**：判定偏置如果是随机的，可以通过多票平均掉；但 self-preference 偏置是**有方向的**（偏向同族输出），会系统性地抬高生成侧成果的评分。因此判定与生成必须异构——这不是为了多样性而多样性，而是因为偏置有方向、且方向与「放过错误」一致。
4. **从「相关错误」反推**：实证表明模型错误高度相关，且更强模型的相关性更高。这意味着「用更强模型做判定」本身不能消除共享盲区，只能提高单点正确率；因此第 3 条的异构是必要的补充，而最终兜底仍然是证据锚点与独立验证信号源（ADR-0006 的底线认知）。分配策略不能被当作相关错误的解药。
5. **从「反向案例」反推**：反向案例说明分配取决于认知负荷的分布。若把「生成弱 / 判定强」写成不可动摇的公式，在编排难度高的流程上会系统性选错模型；因此必须把「分配依据是认知负荷」写进决策，而不是写在备注里。同时保留实验对照（见关键实现注意点 5），把这条口径从宣言变成可检验的假设。
6. **从「零代码可扩展」反推**：如果异构约束只写在文档里，新增角色时必然有人漏配。把约束放进 schema 并由平台校验，才能让「判定与生成异构」成为结构保证，而不是人的自觉。

## 被否方案的否决理由（逐一）

- **方案 A（同构对称）**：否决于 self-preference bias 与共享盲区。判定与生成同源时，投票记录会被记为「独立一致」，制造虚假可信度——这是比没有投票更危险的状态。
- **方案 B（统一最强模型）**：否决于成本与相关性的双重不利：生成侧调用量最大，成本线性放大；而更强模型跨架构的相关性反而更高，无法解决共享盲区。它同时放弃了异构带来的独立性收益。
- **「用同一模型的不同提示词角色代替异构」**：否决为不充分。同模型不同提示词无法消除 self-preference bias（偏置来自模型对自身输出的熟悉度/困惑度），错误相关性也显著高于跨模型。它只能作为「异构」的弱补充形态，不能替代。
- **「生成用强模型、判定用弱模型」**：否决于方向搞反了——判定侧是账本可信度的最后一道关，把它交给弱模型等于把风险放在最不该省的环节。
- **「按成本预算动态选模型，不固定档位」**：否决于可审计性。投票记录需要记录 `model_id@version` 以支持回放与可复现；动态漂移的分配会让「两次相同的决策点为什么结论不同」无法归因。档位可以按流程配置，但单个决策点的模型必须在投票时固定并留痕。
- **「把异构约束交给人的配置纪律」**：否决于必然漏配，且漏配的后果（虚假独立一致）难以在事后发现。约束必须由平台校验。

## 关键实现注意点

1. **异构的判定必须是可机验的**：平台在加载 agent/gate 定义时校验 `heterogeneous_with` 关系；判定角色的模型家族与其声明的生成角色存在交集即报错。家族判定按 provider + 型号系列，而不是按调用入口（同一模型通过不同 API 调用不算异构）。
2. **异构的最小实现口径**：至少满足「不同模型家族」；跨供应商更佳。允许的弱形态是不同型号档位（如不同规模）但不接受「同型号不同提示词」。
3. **实验三必须加编排侧对照组**：现有实验设计只有「生成侧换模型」一个变量，无法检验修正口径。应增加「强编排 + 弱执行」对照组，测完成度、返工轮次、介入次数，顺带采集 token 成本与人工分钟数（主项为节省的人工时间与介入分钟数，token 成本仅作参考项）。
4. **成本假设的成立区间要写清楚**：需实测两个系数——生成侧的节省系数与判定侧的放大系数；若判定侧成本随上下文膨胀而快速增长（放大系数高）、或投票 k 值过大，假设可能不成立。给出告警阈值（k 与放大系数的初值），超出即回到「降低 k 或降低判定上下文体积」。
5. **prompt cache 与静态前缀**：多 agent 共享的上下文包（系统提示 + 需求快照）应放在 prompt 前缀并尽量保持静态，这是驱动层白拿的成本优化；判定侧上下文膨胀是成本假设的主要风险，因此注入层剪裁（ADR-0003）同时也是成本控制手段。
6. **与外部异构调度的区分要写进入接文档**：本方案约束的是「判定与生成的关系」与「留痕字段」，不规定底座如何做模型路由；组织已有调度能力时，平台只校验关系声明与记录实际使用模型。
7. **留痕字段**：每条投票/判定记录必须包含 `provider`、`model_id@version`、角色 id 与生成方 id，使「异构性」可被事后审计，而不只是加载期校验。
8. **不引入的机制**：不做自动模型能力评估与动态升档。档位是配置项；能力变化由人评审更新配置，更新走 ADR 记录（避免「平台偷偷换模型导致历史结论不可复现」）。
