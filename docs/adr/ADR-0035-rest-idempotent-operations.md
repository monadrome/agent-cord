# ADR-0035 ｜ REST 请求身份与幂等执行生命周期

- 状态：accepted（用户授权的原型优化）
- 日期：2026-10-07
- 关联：ADR-0021（写命令幂等）、ADR-0027（配置重载）、ADR-0032/0033（协调操作）、ADR-0034（启动事实）
- 来源：持续 SDLC 优化与重复写命令的共享入口审查

## 背景

响应后缓存不能阻止同键并发命令进入 handler。同路径不同输入会返回旧响应，用户无法确认实际保存了什么。重载与协调创建各有局部 Promise 映射，但其它命令没有保护；副作用已发生、响应尚未缓存的崩溃还可能导致重复派发。

## 备选方案

1. 每个 route 维护并发映射：重复实现，跨路由同键不能统一裁决。
2. 仅增加内存锁和 body hash：仍无法识别重启前未完成的请求。
3. 共享生命周期 + 持久化请求占位（选定）：绑定请求身份，先占位后执行，终态响应成功缓存后再唤醒重复请求。

## 决策

1. 所有声明 idempotency=true 的 REST 写命令走同一个钩子。key 绑定 method、精确 URL 和 input_hash；hash 依据规范化结构化 body，区分 absent 与显式 JSON，忽略对象字段顺序，保持数组顺序和字符串内容。只持久化 hash，不存请求正文。
2. 首个请求在 preHandler 的首个 await 前建立进程内 owner，SQLite 同步插入 pending 占位成功后才允许 handler。并发相同身份请求等待 owner 最终响应，复用 status/body/content-type；不同身份立即 409，不能污染或释放 owner。
3. 成功响应从 pending 条件更新为 completed 并落库，之后才发布给等待者。缓存命中返回第一次响应，跨重启保持一致。响应持久化失败返回 500，保留 pending，不能宣称成功或允许同键重做。
4. 4xx 属已知拒绝，删除 pending 后允许修复/重试；并发等待者仍得到同一次失败响应。5xx 可能发生在副作用之后，保留 pending；之后或重启的同键请求返回 409 idempotency_incomplete，要求查看实际状态，确认结果后以新键执行新操作，不自动猜测或重放。
5. SQLite 增 input_hash 与 state（pending/completed），兼容旧表。旧缓存无输入身份时返回 409 idempotency_legacy，保留原记录；不能用当前请求覆盖历史指纹。条件写验证同键身份与状态，不能忽略冲突并向用户返回未被保存的结果。
6. 生命周期覆盖响应、异常、连接中断的清理，只有 owner 能释放对应内存占位。移除 reload/coordination 的局部映射，业务 service 仍保留同需求互斥和事件语义。只读校验/doctor 不产生业务写事实，保留现有不要求 key 的入口。

## 理由（第一性原理推导）

- 重放必须证明同一次请求，而 key 和路径不能证明 body 一致。
- 并发请求不能先各自改变状态再决定哪一个响应获胜，执行权必须在业务前确定。
- 崩溃后未知不能伪装成未执行，持久化 pending 给宿主一个可检验的证据边界。

## 被否方案的否决理由（逐一）

- 路由局部映射：每新增命令都需重复实现，跨路由依然存在缝隙。
- 内存锁：重启清空后会重新派发未知结果的操作。
- 自动重试 5xx：服务可能已经追加事件或写文件，异常不能证明无副作用。

## 关键实现注意点

- 本原型明确拒绝未知结果，不承诺 SQLite 与事件/文件写入形成原子事务，也不自动修复 pending。
- 正常运行需单进程；跨进程持久 pending 可阻止同键双 owner，但不是 worker lease 或完整分布式队列。
- key 长度有界，输入 hash 不含凭据原文；成功响应仍沿用已有 API 的公开字段边界。
- 连接断开不是业务取消，若 handler 仍运行，重复请求等待其最终事实，不因观察超时重新派发。
- 写命令响应限可缓存文本/Buffer/空响应；流式结果明确返回未确认错误，不能把流对象 JSON 化或留下永不收束的等待者。SSE 只读路由不参与幂等执行。
- 覆盖所有已有写入口、字段顺序、不同输入、并发冲突、4xx 重试、5xx/缓存故障、重启 pending、旧表兼容。

## 证据来源

1. app.ts 的 preHandler/onSend 与两个局部 Promise 映射。
2. IndexStore 的 idempotency_keys 响应缓存与 INSERT OR IGNORE。
3. run/coordination 的业务前槽位和事件存储失败边界。
