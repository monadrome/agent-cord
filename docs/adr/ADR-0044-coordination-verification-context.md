# ADR-0044 ｜ 协调者读取结构化机器验证观察

- 状态：accepted（本地原型实现）
- 日期：2026-10-08
- 关联：ADR-0032（协调提议）、ADR-0040（验证事实）、ADR-0041（源码输入）、ADR-0043（提议新鲜度）
- 来源：阶段 30 对协调上下文证据面的审查

## 背景

协调者已有需求文档、账本、进度和源码摘要，但不知道当前机器验证是缺失、失败、过期还是通过。验证结果单独更新时也不会改变协调语义输入。

## 决策

宿主通过 ContextSessionAgentOptions.read_verifications 提供严格结构化的验证观察。server 只投影绑定流程声明的 verification-passed 检查，取当前 run/节点/验证 ID 的最新结果，使用既有 readNodeInput 重算新鲜度。缺失、非法、不可读、旧输入或取消运行不得声明为当前有效结果。

观察只包含身份、状态、输入/命令/源码摘要、退出码与有限原因枚举；不含 summary、日志、任意事件正文、凭据或工具输出。最多 128 项，超限或宿主返回值非法时不派发模型。

有验证观察时协调 input 使用 v3 域，完整观察参与输入 hash；started/completed 只记录 verification_context_hash。调用结束、查询与采用前重读观察，结果变化使提议 stale 或不可采用。未配置观察且列表为空时保留此前 v1/v2 身份。

CoordinationEvidence 增加 verification 来源，可引用观察中最新且 current=true 的结果事件 ID，包括如实表示失败的结果。缺失、过期和无法验证的结果不能作为有效引用；结果引用不代表 gate 通过，推进/完成规则仍由 workflow 决定，人工 gate 不改变。

## 理由

协调者应基于可核验的机器状态决定等待、询问或下一步，不能把 findings 文本当作测试事实。受限投影与内容 hash 支持新鲜度且避免注入历史日志。

## 边界

观察依赖受信宿主与声明范围的完整性，不认证外部 CI 身份或模型结论。相同结果重复落盘会改变事件引用并使旧提议失效，这是可审计的证据版本变化。整个工作流状态依然由现有事件与执行器控制。

## 验证

核心验证严格结构、prompt 数据边界、来源校验和在途变化；真实 REST/driver fixture 覆盖缺失、失败、恢复、过期、取消、跨版本及采用前重检。
