# ADR-0034 ｜ SDLC 执行版本隔离与启动绑定事实

- 状态：accepted（用户授权的原型迭代）
- 日期：2026-10-07
- 关联：ADR-0022（发布绑定）、ADR-0030（恢复/审批）、ADR-0032/0033（协调与采用）
- 来源：持续 SDLC 优化目标与跨版本进度复用审查

## 背景

run 登记绑定 SDLC 版本，但节点、gate、任务与快照只以 workflow_id 定位。新版本即使定义改变，也可能被旧 node.exited 直接跳过；相同定义的新版本可能复用旧 worker 和人工等待。取消和投影同样会跨版本混用。仅靠任务输入 hash 无法修复已退出节点的跳过。

## 备选方案

1. 把版本拼入 workflow_id：改变公开 DSL 标识与人工引用，破坏已有契约。
2. 每个 run 独立进度：破坏同版本重新 start 的断点恢复。
3. 稳定执行版本 + 显式启动绑定事实（选定）：保持 workflow_id，新增 workflow_revision，所有作用于流程的读写使用同一作用域。

## 决策

1. workflow_revision 为 SHA-256，覆盖规范化完整 WorkflowDef 与发布绑定 `{id, version}`，不含时间戳、事件序号、run_id 或环境。相同发布版本保持稳定，不同定义、发布版本或发布名称相互隔离。
2. executor、NodeRunContext、HumanGateContext、CheckerContext、SnapshotOptions 和协调输入可携带执行版本；workflow/gate/agent.task/协调轮次事实记录该值。统一匹配同时验证 workflow_id 与 workflow_revision。带版本读者不接受旧无版本事件；不带版本的库调用保留无版本兼容模式，不继承带版本事件。
3. 快照的进度/等待、checkpoint、审批求值、事件 checker、run 终态/时间线/当前节点/审批和协调指纹都在该作用域内；账本与需求文档仍是 session 级共享输入。取消只影响该执行版本，等待 ID 继续使用全局 ULID。
4. server 从发布绑定生成并固定版本。run 登记持久化 workflow_revision；恢复时缺失版本身份或发布定义与登记不一致必须 fail-closed。旧无版本事实保留审计，不猜测其发布归属，不批准或自动复用到新版；用户重新 start 可产生新的已绑定版本事实。
5. 新增 workflow.run.started 事实，包含 run_id、workflow_id、workflow_revision、sdlc_id/sdlc_version 和可选 coordination_round_id。登记后、派发前落盘；采用事实同样在派发前落盘。恢复要求启动绑定事实与登记一致，协调 run 仍要求 adopted 事实。SQLite 兼容新增可空列，索引丢失时从 started 事实重建 run 绑定与当前版本，再投影终态/恢复。
6. 同一需求的当前版本由最新 run 绑定决定；恢复只推进最新 run，历史版本保留事实与记录，不自动推进、不伪造取消。旧版本审批在当前版本下不可决策；显式重新 start 旧发布版本可恢复它自己的进度与门禁。
7. 协调轮次固定其绑定版本，输入 hash 包含版本；不同版本不能把旧退出节点当作新进度。采用只能启动提议绑定的版本，不能由请求体覆盖。历史已采用轮次重复请求仍返回原 run，不重新派发。

## 理由（第一性原理推导）

- 工作流标识、发布版本与运行尝试是三个对象。恢复需要稳定的版本边界，不能依赖名字或本次进程。
- 新版本只有在自己的事实证明节点完成时才能跳过；任务输入校验不能替代已退出节点的版本归属。
- 索引是派生数据，发布绑定不能只留在索引，否则删除索引会改变需求的当前工作流。

## 被否方案的否决理由（逐一）

- 改 workflow_id：公开标识混入宿主存储格式，影响所有引用和展示。
- run_id 隔离：每次恢复都丢失已有进度和人工等待。
- 仅定义 hash：无法区分相同定义的不同发布版本和名称。
- 猜测旧事件归属：历史没有证据就不能作为新版放行依据。

## 关键实现注意点

- 版本指纹使用纯函数与结构化数据，不改变 hash/reducer 的确定性。
- 不隐式迁移或改写旧事件；无版本库模式与 server 显式版本模式互不混用。
- 人工决策绑定等待 ULID与求值 hash，并验证当前 run 的执行版本；共享账本事件仍可供版本内门禁读取。
- 故障注入覆盖启动绑定/采用落盘之间的窗口、索引删除、旧表迁移和发布定义被外部改动。
- 当前仍是单进程原型，跨进程 lease 与文档多文件事务不在本次范围。

## 证据来源

1. executor.scan / snapshot / SessionService / RunService 的 workflow_id 单键过滤。
2. SdlcService 发布版本与 run 登记的绑定字段。
3. 既有 checkpoint/审批新鲜度测试与协调采用恢复边界。
