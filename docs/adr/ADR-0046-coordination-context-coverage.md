# ADR-0046 ｜ 独立协调文档首尾覆盖与预算分配

- 状态：accepted（实现选型）
- 日期：2026-10-08
- 关联：ADR-0032（独立协调）、ADR-0043/0044（输入身份）
- 来源：阶段 32 的长需求与报告覆盖审查

## 背景

完整文档 hash 只能证明输入身份，不能证明模型看过变化部分。固定前缀截断丢失末尾追加要求，顺序填充总预算可能省略后续评审报告。

## 决策

独立协调使用共享 readCoordinationSnapshot，以每文档最多 20,000 字符的首尾片段采集输入。普通 readSnapshot 默认仍为前缀模式。协调 prompt 的剩余字符预算在有内容的文档间均衡分配，短文档剩余额度回流；固定元信息和片段索引超过预算时拒绝派发。

片段索引记录 file、原文字符范围、实际纳入数与省略数；正文按这些范围展示。省略内容不得被模型视为已核验。所有范围使用 JavaScript 字符串 UTF-16 偏移，完整原文 hash 与长度仍进入快照和输入身份。

协调输入使用 v4 域及明确的上下文策略版本，完成、查询和采用共用相同采集规则。旧输入身份的提议保留历史但不继续被判为当前有效；不重放旧模型调用。

## 理由

有限预算下覆盖需求开头、最新附记及各份报告，比按文件顺序耗尽预算更符合协调职责。确定性选片段不新增事实或模型摘要，仍可对照磁盘原文核验。

## 边界

首尾覆盖不保证包含中间所有关键要求，不证明文档结论正确，也不替代机器验证或人工 gate。字符预算不是模型 token 预算。正文与片段索引仅发给当次 driver，轮次事件仍只保存 prompt/input hash；原文不落事件。
