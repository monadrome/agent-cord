# ADR-0028 ｜ 协调快照一致性与任务失败恢复

- 状态：accepted（已实现）
- 日期：2026-10-06
- 关联：ADR-0003（最新快照）、ADR-0023（协调 agent）、ADR-0025（重试）、ADR-0026（provenance）
- 来源：最新需求快照与 coordinator 文件写回审查

## 背景

快照此前读取磁盘 `ledger.yaml` 后再读事件，账本投影可能滞后，进度还混入其他 workflow 的同名节点。快照准备与 artifact 写回错误未统一记为任务失败；驱动配置错误仍可能被 retry 循环重复尝试。词法路径检查不能识别链接，固定 `.tmp` 文件也可能被链接到目录外；workflow 还能声明事实文件作为 artifact。

## 备选方案

1. 每节点 `rebuildLedger()` 后再读文件：引入不必要的磁盘写入，账本与进度仍可能使用不同事件批次。
2. 所有异常吞掉并使用空快照：worker 会继续基于缺失信息工作，破坏最新快照承诺。
3. 同批次事件投影、受控文档文件访问与明确失败终态（选定）：直接复用 reducer，从同次事件读取构建账本、进度和指纹；准备/写回错误统一落任务事件。

## 决策

1. `readSnapshot` 只读取一次有序事件流，用纯 reducer 生成 ledger 摘要，同时从该批次派生 title、progress、event seq 和 chain hash。读取快照不修改磁盘 ledger。
2. `SnapshotOptions.workflow_id` 限定工作流进度，coordinator 始终传当前 workflow。账本仍属于需求 session；摘要保留 conflict 标记，上下文明确冲突需人工处理。
3. 文档内容单独采集，其完整 hash 参与 snapshot_id。文件缺失是合法状态；读取异常必须拒绝派发，不能把权限、类型错误等伪装为缺失。文件与事件流不构成操作系统级原子快照，指纹只声明实际读取到的输入。
4. coordinator 读写的文档必须是 session 内的普通文件路径。拒绝路径穿越、绝对路径、符号链接、硬链接与事实/管理文件（events.jsonl、ledger.yaml、agents.yaml、.git、.index、.sdlc）。根目录以真实路径为边界，写入先验证父目录，使用独占随机临时文件、fsync 和 rename，并在失败时清理临时文件。
5. `agent.task.completed` 可选 `failure_stage`（snapshot / configuration / driver / artifact）和 `retryable` 字段。快照准备、配置解析、driver、写回失败都产生 started/completed；永久路径或配置错误不重试，瞬态故障按节点策略重试，每次重新生成快照。
6. 唯一无法由任务失败事件兜底的是事件存储追加失败：错误必须上抛给宿主，不能伪造成功或继续派发。这是 NodeRunner 不抛错约定的存储故障例外。

## 理由（第一性原理推导）

- 账本是事件流的投影，直接使用同一批事件是获得一致基线的最短路径。
- 节点 id 只在 workflow 内标识进度，跨流程混合会把未完成输入当作已确认产物。
- 失败必须留可恢复的事实；没有 completed 的普通异常会使审计无法区分中断与明确失败。
- 声明 artifact 仅授予文档写回能力，不能授予覆写事件或运行配置的能力。

## 被否方案的否决理由（逐一）

- 每节点刷投影：增加文件副作用，仍不能保证同批事件基线。
- 空快照兜底：掩盖不可读输入，会继续放大错误。
- 固定临时文件名：存在链接覆盖和任务间临时文件冲突。
- 存储错误也吞掉：无法证明任务失败事实已持久化。

## 关键实现注意点

- 复用现有纯 reducer/hash，不修改其算法；旧事件缺少新字段仍可恢复。
- 文件保护约束 coordinator 的文档访问，不是 worker 操作系统沙箱，也不保证抵御并发恶意替换父目录；CLI 的权限约束仍由 driver 与宿主负责。
- 离线测试涵盖滞后/损坏投影、同名跨流程节点、符号链接/硬链接、写回失败恢复、不可重试配置与事件追加故障。

2. ADR-0023 / ADR-0025 / ADR-0026 对最新上下文、任务终态、恢复与路径作用域的承诺。
