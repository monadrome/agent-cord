# ADR-0006 ｜ 独立盲评投票，不辩论

- 状态：accepted（设计定稿，代码未实现）
- 日期：2026-09-24
- 关联：ADR-0005（账本 `投票记录` 字段）、ADR-0007（判定与生成必异构）、ADR-0013（投票执行器的实现）
- 来源：方案提案 §6.2 通用投票机制设计（v1.1 按外部文献证据重做）；落实确认点 CP-14、CP-15（待确认）、CP-26、CP-31、CP-32（已确认）

## 背景

项目需要一套**通用投票机制**：非重点任务由多个 agent 达成共识。这条已作为定稿共识，但「怎么达成」有多种路线，而不同路线的有效性证据强度差别很大。

需要回答四个问题：

1. 多个 agent 之间是**互相辩论收敛**，还是**各自独立判断后投票**？
2. 投票用几个 agent（k 值）、什么放行规则？
3. 如何保证「独立」是真的独立，而不只是形式上多了一次调用？
4. 什么决策点可以投票？——如果所有决策点都投，成本与风险如何控制？

四个问题里隐藏着一个容易被忽略的结构性问题：**投票的有效性有前提**。经典的自一致性方法（同一模型多次采样 + 多数投票）在数学与选择题上提升显著，但前提是**答案可自动判定且采样相互独立**。语义理解类决策不满足这两个前提。更麻烦的是，模型的错误是**系统性相关**的：两个不同模型同时答错时，相当高比例的情况是错在同一个答案上，且跨架构、跨供应商的相关性依然显著。这意味着「多模型一致」不等于「正确」，一致本身可能只是共享盲区的表现。

## 备选方案

### 方案 A：多 agent 辩论（互相看对方的推理后收敛）

- **是什么**：多个 agent 就同一决策点轮流发言、互相质疑、迭代修改立场，最终收敛到一致结论或多数结论。
- **优点**：有正面实证——多 agent 辩论在数学/策略/事实任务上能提升准确率，agent 越多、模型越强效果越明显；辩论过程本身可作为一种解释材料；对「结论需要被多方理由支撑」的场景有吸引力。
- **缺点**：
  - 系统 benchmark 显示现状形态的辩论**不能稳定跑赢**自一致性/多路径集成，且对超参敏感（agent 数、轮数、提示词风格都会改变结论）；
  - 有理论结果证明辩论不改善期望正确率——辩论诱导的信念轨迹是鞅，同构 agent + 均匀信念更新下期望正确率保持不变；
  - 成本显著更高（多轮、多 agent、上下文累积）；
  - 辩论会诱发从众：多数 agent 共享错误观念时，少数 agent 会顺从而非反驳（echo chamber / tyranny of the majority）；
  - 辩论的一致性具有误导性——错误会在辩论中互相说服并收敛到错答案，因此「辩论达到一致」不能当作可信度信号。

### 方案 B：单 agent 自评（自己生成、自己判断）

- **是什么**：一次调用内让模型生成结论并自评置信度，或换提示词让同一模型复核一遍。
- **优点**：成本最低、延迟最低、实现最简单。
- **缺点**：同源错误无法被发现——自评与生成共享同一套先验与盲区；LLM 评委系统性偏爱自己模型的输出（self-preference bias），自评的偏置方向恰好是「给自己打高分」。
- **证据关系**：方案 B 的问题正是方案 C 存在的理由；它同时也是「判定 agent 必须与生成 agent 异构」（ADR-0007）要解决的同一个偏置。

### 方案 C：k 个异构模型独立盲评投票（不共享中间推理）

- **是什么**：k 个异构 agent 各自独立探索后提交结构化结论（选项 + 证据锚点 + 理由），互不见中间推理；按放行规则汇总；分歧时留痕并升级人工。
- **优点**：
  - 是「够用且便宜」的路线：有效性有实证（可机判答案 + 独立采样场景），成本是 k 次独立调用，无多轮累积；
  - 与账本结构天然吻合——投票结果直接落条目字段（各票结论、证据锚点、少数派理由），可审计、可回放；
  - 允许程序化检查独立性（锚点重合、净输入审计），比辩论更可机验；
  - k 值收益呈幂律饱和，因此在成本约束下小 k 是合理的，不需要大 k。
- **缺点**：
  - 有效性依赖独立性，而独立性是**必要非充分**——相关错误无法通过投票消除；
  - 需要在工程上强制隔离，否则「独立」名存实亡；
  - 语义类决策即使全票一致也不该直接确认，这限制了免人工通道的适用范围。

## 决策

**采用方案 C。共识形成用 k=2~3 异构模型的独立盲评投票，不引入辩论环节。**

配套规则（全部为设计定稿口径）：

**适用范围（难度门）**——投票只用于「非重点 + 可机验（证据锚点类型 ∈ {代码, 用例}）+ 可逆」的决策点。理由：预注册研究表明难题上多数投票会系统性反噬。投票必须前置难度门，只投有先验把握的决策点；不可逆/高风险决策仍走人工确认。

**k 值与放行规则**：

- k = 2~3 为初值（文献中 debate 系工作普遍用 2~3 个 agent；增大 k 的收益呈幂律饱和）。
- **2/2 一致 → `confirmed`**，仅限带**可机器验证证据锚点**（代码/用例）的决策点。
- **语义理解类决策不进投票队列**（不可机验，不满足难度门硬条件），直接落 `needs_verification` 交人工；若团队配置性发起参考投票，其结果也不落地 `confirmed`——这是「一致但同盲」在方案内残留的最大免审通道，语义类决策无法被机器验证信号兜底。
- **3 票制 2:1 分歧 → `needs_verification` + 少数派理由留痕**：少数派的结论、理由、证据锚点必须写入投票记录并一并推给人。依据：3 agent 实验中 39.1% 的样本出现 2:1 分裂，其中 25.5% 少数派才是对的——没有理由留痕，人无法判断。

**独立性保证（比算法更重要）**：

1. **盲评/匿名化**：投票 agent 之间不共享中间推理，各自独立探索后提交。该禁止项从「建议」升级为**协议强制项**（由 harness 强制，不由提示词约束）。
2. **异构**：使用不同模型或不同提示词角色（异构集成在等预算下优于同构，有实证）。
3. **判定 agent 与生成 agent 必须异构**（消除 self-preference bias，详见 ADR-0007）。
4. **证据锚点独立度检查**：两个 agent 结论一致但证据锚点重合（Jaccard ≥ 0.5 或一方集合是另一方子集）→ 视为**疑似同源错误** → 强制升级人工而非 `confirmed`，投票记录中记 `independence_flag: anchor_overlap`。

**底线认知**：异构是**必要非充分**条件。大规模实证表明两个模型都答错时约 60% 的情况错在同一个答案上，且跨架构、跨供应商的错误相关性依然显著，模型越大越准相关性越强——异构不能替代证据锚点与独立验证信号源（最终兜底）。

**度量口径**：独立一致度按**决策点难度分桶统计**，并与推翻率联合解读；不设固定健康区间。**100% 一致在难题桶中是相关错误警报，而不是健康信号**。

## 理由（第一性原理推导）

1. **从「目标是什么」反推**：投票要解决的是「这个决策点上的判断是否正确」，不是「这些 agent 能否说服彼此」。说服过程与正确性没有单调关系，甚至可能反向（错误互相说服并收敛）。因此应选择与正确性直接挂钩的机制：独立判断 + 汇聚。
2. **从证据强度反推**：盲评投票的有效性有明确前提与量化边界（可机判答案、独立采样、k 增大后幂律饱和），可以被工程设计；辩论的有效性结论不稳定（对超参敏感、跑不赢自一致性、理论证明不改善期望正确率），无法作为机制的地基。选证据更硬的那条路，即使它的上限看起来低一些。
3. **从成本反推**：辩论的成本是多轮 × 多 agent × 上下文累积，而收益不确定；盲评的成本是 k 次独立调用，上限明确。在「token 成本是噪声级、人工介入时间是真实成本」的结论下（见 ADR-0001 与关键实现注意点），把预算花在**增加独立验证信号**上比花在增加对话轮次上更划算。
4. **从「独立性的可执行性」反推**：独立不能靠提示词要求（agent 完全可以无视「不要看别人的答案」）。可执行的独立性只有两条：进程/文件系统隔离（ADR-0011、ADR-0013）与**事后可检查的独立性度量**（净输入审计 + 锚点重合度）。因此本 ADR 把「锚点独立度检查」写进机制而不是留给观察——这一步把相关错误的验证方法从「离线统计」前移到「运行时强制」。
5. **从相关错误的量化事实反推**：既然「两个模型都错时 60% 错在同一答案」，那么「2/2 一致」本身不具备充分的说服力。因此免人工通道必须被限定为「一致 + 锚点可机验 + 锚点独立」，三个条件缺一不可；语义类决策因无法机验，即使满足独立性也不能免审。
6. **从「少数派价值」反推**：2:1 分裂中少数派有约四分之一概率是对的。多数规则会系统性地丢掉这部分信息，因此少数派的**理由**必须留痕并推给人——人判断的依据不是票数，而是理由与证据。这条决定了投票记录的字段设计（`少数派理由` 在 2:1 时必须非空）。
7. **从「难题上投票反噬」反推**：既然在难题上多数投票会使准确率下降（模型系统性地一致趋向错误答案），那么投票的适用范围必须前置筛选。难度门不是成本优化，是正确性要求。

## 被否方案的否决理由（逐一）

- **方案 A（多 agent 辩论）**：否决于有效性的不稳定（跑不赢自一致性、对超参敏感）+ 理论上不改善期望正确率 + 成本更高 + 从众效应。它的正面证据（部分任务上提升准确率）不足以支撑把它作为机制地基；且辩论产生的一致性不能作为可信度信号，与本项目「一致即需可复核」的取向冲突。
- **方案 B（单 agent 自评 / 同模型复核）**：否决于同源错误与 self-preference bias。自评与生成共享先验，无法发现系统性盲区；同模型复核等于用同一把尺子量自己。
- **「用多数表决（k≥3，2/3 放行）」作为默认规则**：不否决投票本身，但否决把 2/3 当作默认免审通道。2:1 分裂比例高（39.1%）且少数派正确率可观（25.5%），多数规则有约 10pp 量级的理论可回收错误率；因此本方案把 2:1 一律导向 `needs_verification`，而非直接放行。
- **「语义类决策也走 2/2 免人工」**：否决于无法机验。语义决策的一致可能来自共享盲区（且难题上系统性趋同错误已被量化），缺少机器验证信号兜底时，一致不能替代复核。
- **「让投票 agent 看到彼此的答案以提高一致性」**：否决于从众效应与匿名化证据。看到他人答案会诱发顺从（echo chamber），而匿名化被证明可降低身份偏置；两条证据同向。
- **「投票 agent 用同一模型不同提示词」**：不作为充分条件，仅作为「异构」的弱形态被允许。同模型不同角色提示词的错误相关性显著高于跨模型，因此「判定与生成必须异构」这条约束不接受同模型不同提示词的替代方案（详见 ADR-0007）。
- **「加大 k 以提升可信度」**：否决于收益幂律饱和与成本上升。k 增大的边际收益迅速衰减，而成本线性增长；正确做法是先用难度门筛掉不该投的决策点，再在小 k 上做参数校准。

## 关键实现注意点

1. **投票记录 schema（与 ADR-0005 账本字段衔接）**：

```yaml
投票记录:
  决策点: {id, 结构化选项集, 难度桶, 可机验性: true|false}
  k: 3
  各票:
    - {agent_id, provider, model_id@version, prompt_hash, option_permutation,
       结论, 证据锚点[], 置信度, usage, request_id}
  统计: {原始一致率, fleiss_kappa, gwet_ac1, anchor_overlap: <值>}
  判定: confirmed | needs_verification | escalated_anchor_overlap
  少数派理由: null | {结论, 理由, 证据锚点[]}   # 2:1 时必填，随 needs_verification 推给人
```

2. **`model_id` 必须带版本后缀**（例如形如 `<模型名>-<快照日期>`），并写入投票记录；否则回放实验的可复现性落空。同时记录 `prompt_hash` 与选项随机化置换，供反查 position bias。
3. **盲评审计常态化**：把「净输入审计」做成门禁的校验器——检查该票的净输入中是否出现其他票的输出或人工结论关键词，命中则该票作废重跑。这是把「禁止互见中间推理」从提示词升级为 harness 强制的落点。
4. **锚点独立度的比较口径**：只用**规范化后的符号锚点**（文件路径 + 顶层符号路径）做集合比较，行号不参与（漂移 + 巧合重合都会污染）。重合度用 Jaccard 相似度；阈值 0.5 与「一方是另一方子集」为初值，校准输入来自回放实验的锚点重合度统计。注意只需处理「一致 + 重合」这一个危险象限——「一致 + 锚点完全不同」是独立验证的健康信号。
5. **难度门的判定条件是配置而非代码**：三个硬条件——① 非重点：不在重点决策点清单内；② 可机验性：决策点的证据锚点类型 ∈ {代码, 用例}；③ 可逆性：不在「不可逆动作清单」内。不满足任一条件者不进投票队列，直接落 `needs_verification` 交人工。软信号（触发式升级同款哲学）：决策点标签属于契约/跨模块语义时，即使可机验也强制 k=3；历史推翻率高的标签类别自动降置信度并强制投票（推翻率回流机制的消费端）。
6. **一致度指标体系**：主指标用机会校正的一致度（Fleiss' κ / Gwet's AC1），原始一致率作辅助，并直测「一致但错率」；按难度分桶报告，与推翻率联合解读。禁止使用固定健康区间（如 70–90%）。
7. **失败与弃权语义**：单票判定失败重试 1 次仍失败 → 该票记 `abstain`，不阻塞整体；弃权票不参与一致度分母的口径需在 schema 中明确。
8. **禁止项清单（协议强制）**：投票 agent 之间不共享中间推理、不共享会话状态、不通过群聊沟通；协调 agent 不得把 A 票的 transcript 喂给 B 票；投票 transcript 按 agent 分目录落在该需求的 `votes/` 下、随 `VoteRecord` 引用，仅作审计与回放，不入任何 agent 的上下文。
9. **与门禁的挂载关系**：投票本身是门禁的一个校验器（`checks: [投票]`），不是独立机制；因此「新增一种投票规则」= 改配置，符合零代码原则（ADR-0014）。
