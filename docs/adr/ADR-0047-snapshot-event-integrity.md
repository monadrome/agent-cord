# ADR-0047 ｜ 最新快照与协调轮次的严格事件读取

- 状态：accepted（实现选型）
- 日期：2026-10-08
- 关联：ADR-0020（事件流）、ADR-0028（快照）、ADR-0045（验证证据）
- 来源：阶段 33 的快照事实完整性审查

## 背景

readSnapshot 使用普通 readOrdered，损坏完整行会被跳过，外部 session 的合法 envelope 也未拒绝。损坏的待审/失败事实可能消失，外部进度或共识可能进入当前快照。未声明机器验证的协调轮次没有阶段 31 的严格读取保护，旧提议可能继续显示 current。

## 决策

EventStore 增可选 readOrderedStrict，原生 JsonlEventStore 对当前读取的每行校验 envelope 和 session，坏行/未完成尾部/外部事实即拒绝，不因历史诊断缓存阻止已修复的当前读取。普通诊断读取仍可展示合法部分，打开时原子尾行恢复语义保持不变。

核心 readSessionEvents 作为共享入口，优先使用严格端口，并统一校验返回的 envelope/session。旧自定义端口保留 readOrdered 兼容，并在提供诊断时拒绝 unparsable_line；旧端口本身须兑现返回全部事件的原契约，helper 无法还原其内部隐藏的数据。

快照、验证和协调轮次读侧使用同一入口。协调创建先严格预检再写 requested；历史查询/采用在事件不可读时拒绝，不能回退旧成功。冷启动协调恢复按 session 隔离完整性错误，保留原未完成事实，服务继续健康且不重放调用；修复后可读取，重新启动服务再执行正常中断恢复。

明确取消请求遇到读取/落盘错误时，仍 abort 进程内确认匹配的在途轮次并等待收束，接口保留原错误，不伪造 cancel_requested 或成功响应。停止是用户已请求的动作，不能因事实流不可读而继续付费运行；可写的 completed 仍如实记录 cancelled，无法写入则由正常中断恢复处理。

## 理由

最新快照必须同时证明材料身份和读取完整性。丢失待审事实后的旧成功不能成为可采用提议，历史诊断也不能永久锁死已修复的当前材料。

## 边界

严格读取校验 envelope、session 和当前行完整性，不改变 payload 的前向兼容，不替代 doctor 哈希链/账本诊断，不自动修改损坏完整行。存储在冷打开时发现坏行仍禁止写入，修复后需重新打开；修复由人工或测试完成。普通 UI 事件浏览与其余 workflow 投影保持已有读取语义，本轮保护快照、验证与协调决策边界。

## 验证

先复现坏行/外部 session 被纳入快照与旧提议继续可采用，再覆盖派发前、在途、查询/采用、活跃读取修复和冷重启隔离。纯 hash/reducer 保持不变。
