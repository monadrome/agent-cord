# ADR-0045 ｜ 验证门禁与协调观察统一证据校验

- 状态：accepted（实现选型）
- 日期：2026-10-08
- 关联：ADR-0040（验证事实）、ADR-0044（协调观察）、ADR-0029（最新证据）
- 来源：阶段 31 的门禁与协调观察一致性审查

## 背景

协调观察已拒绝部分坏结果，但 verification-passed 仍只检查 input_hash 和 status。passed 配合非零退出码、缺少命令摘要等记录可能被机器门禁放行；默认事件读取会跳过损坏行，节点 correlation 不匹配的最新结果还可能被过滤掉而退回旧通过。

## 决策

核心 VerificationResultSchema 统一结果字段约束：身份摘要必须是小写 SHA-256，passed 若声明 exit_code 则只能为 0。未声明或显式 null 的退出码保留未知语义，不能补造为 0。REST 输入与事实 payload 从同一结果契约组合，不接受自相矛盾的写入。

机器门禁和协调投影共用严格验证事件读取及结果解析。事件坏行、非法 envelope、外部 session 或读取故障阻断读取；缺少合法 payload、节点 correlation 不匹配或字段冲突的最新结果不得回退为旧通过。within_node=false 保留显式禁用 correlation 限制的库模式。

当前 run 的 workflow.run.cancelled 事实使其验证证据失效，不能等待索引更新后才阻断。门禁选择同 scope/run/node/验证 ID 的最近事实后再校验；协调观察投影相同结果为 invalid/cancelled，而非把它当作通过。

已有 gate.waiting 在挂起后的输入重检遇到 VerificationInputError 时保留未决等待，与冷恢复的不可读处理一致。REST 继续返回 409 且不写验证或人工决定；源码修复后的合法验证仍可唤醒同一 run。其他异常继续上抛，不隐藏存储或执行故障。

## 理由

模型解释和确定性门禁必须接受相同材料。单一契约减少各消费方的规则漂移，严格读取让损坏的失败证据不会因跳过而被旧成功覆盖。

## 边界

事件仍是不可变事实，写路径不重写历史；旧非法 payload 保留但不提供放行证据。该规则校验结构与状态一致性，不证明宿主确实执行测试，不替代人工 gate 或外部身份认证。全量 doctor 仍负责哈希链诊断，本次不把投影漂移作为事件读取失败。

## 验证

先用 checker/REST 反例复现矛盾结果放行、坏最新结果回退和损坏行被忽略，再覆盖修复后成功、失败、恢复与协调观察一致性。
