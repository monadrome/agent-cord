# ADR-0071 ｜ Goal 源码基线与宿主变更清单

- 状态：accepted（原型已实现）
- 日期：2026-10-09
- 关联：ADR-0041（源码扫描）、ADR-0055/0056（Goal 交付）、ADR-0061（共享 ready）、ADR-0064（验收覆盖）
- 来源：review 指南已有真实测试与矩阵，但变更定位仍依赖 worker 自述

## 背景

当前源码扫描核验字节/路径类型/权限/目录清单，得到 source_hash；ready 和人工审批可以判断源码是否仍新鲜，但 reviewer 不能由 hash 找到具体变更。仅要求“变更”章节非空并不能证明模型列出了所有声明范围内的变更。

## 备选方案

1. 要求 worker 自报 Git diff 或修改文件列表。
2. 复制扫描器给另一个变更服务，分别计算测试与变更身份。
3. 复用同一安全扫描，保存首次源码基线并由宿主计算交付变更清单，ready 共用重算核验。

## 决策

采用方案 3。Goal 可声明 `review_changes: true`；推荐 Goal 模板和示例默认开启。既有发布流程不迁移，未声明的库 hook 保持兼容。

源码 manifest 只含 path/kind/mode/content_hash，无正文；沿用验证摘要域、路径边界与 10,000 项上限，序列化总量另限 1,000,000 字符。扫描器可按需返回 manifest，常规验证 REST 不返回全清单。核验 hook 对启用流程必须提供与 source_hash 一致的 manifest。

第一次 `goal.attempt.started` 在派发前保存 source_manifest，后续尝试不覆盖；冷恢复不能把当前源码偷换成首次基线。ready 的 change_evidence 引用首条合法基线 event_id，记录相对基线的新增/修改/删除及前后元信息。共享函数重新应用完整 delta 到基线，重算结果必须等于实际验证/ready 的 source_hash，拒绝漏项、错引用、重复和伪造。目录和 mode 变化也属于变更；rename 表现为删除+新增，无归因猜测。

宿主生成“宿主源码变更”章节，包含基线来源、前后身份和路径/状态表，与实际测试和验收矩阵同属最终指南。表内文件摘要展示前 12 位便于扫读，完整元信息在事件证据中保留并参与重算。该章节证明声明范围内的观察，不证明所有仓库变更属于当前 agent；初始已有未提交代码是基线的一部分。源码/指南变化沿用原新鲜度校验，ready、恢复、协调与最终人审共享证据解释。

## 理由

1. Reviewer 需要变更定位，测试 hash 和章节占位不能代替真实清单。
2. 一次扫描同时用于被测身份与变更证据，避免两套目录/排除规则漂移。
3. 保存基线和核验完整 delta 让恢复保持原交付语义，不借重启隐藏早期变更。
4. 推荐流程默认开启，旧发布版本遵循原契约；无法读取基线/清单时 fail-closed，不用模型自述补证据。

## 被否方案

- 模型自报列表不能发现漏项或伪造来源。
- 复制扫描器会让测试与清单接受不同输入。
- 用 Git HEAD 代替首次实际源码会把用户原有未提交修改误归因；本阶段不定义自动提交、合入或 worktree 生命周期。

## 验证与限制

覆盖新增/修改/删除/目录/权限/空变更、自动修复两次仍使用首次基线、冷恢复不重置、指南证据来源、错误/缺失 hook、伪造或部分 delta、过期 ready、最终人审拒绝和 ACP/headless 原型闭环。

只证明声明输入的前后观察，不覆盖排除目录或外部副作用，不证明业务测试充分性，不提供恶意 worker 抗篡改或跨进程文件树事务。范围过大时 fail-closed；最终 review、合入、发布和关键 gate 仍人工完成。
