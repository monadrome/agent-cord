# ADR-0027 ｜ 工作区独立 agent registry 与显式重载

- 状态：accepted（已实现）
- 日期：2026-10-06
- 关联：ADR-0023（自定义 agent 注册与协调 session agent）、ADR-0021（REST/server 分层）
- 来源：自定义 agent 的多工作区运行与配置生命周期审查

## 背景

`agents.yaml` 的自定义 args 模板原先注册进进程全局 Map，driver 在每次派发时再次查表。同一进程中两个工作区的同名 agent 会互相覆盖，已构造的 driver 也可能执行后来加载的参数。server 只能在启动时读取配置，用户改角色、模型或启动方式需要重启。

## 备选方案

1. 全局 Map 加工作区名字前缀：仍依赖全局可变状态，删除与在途任务生命周期难以界定。
2. 文件 watcher 自动刷新：编辑未完成的配置可能触发刷新，隐式切换无法对应用户的一次命令。
3. 工作区独立配置快照与显式重载（选定）：编译 agent 配置为独立 resolver；新 run 固定当前 resolver；重载只影响后续 run。

## 决策

1. `agents.yaml` 加载与解析不修改全局 headless 模板表；自定义模板保存在工作区 resolver 内。driver 构造时固定模板、参数旋钮和环境配置。
2. 顶层 YAML 结构错误会拒绝加载；单条定义无效时按字段路径告警并跳过。被配置但无效的别名不能回退到同名内置 agent，解析该别名必须失败。
3. `GET /api/v1/agents` 返回当前 revision、agent 名、协议、来源、模板和告警。输出不包含 env、完整 args、角色 prompt 或 `agents_json`；清单表明配置可解析，不证明 CLI 已安装或凭据可用。
4. `POST /api/v1/agents/reload` 要求 `Idempotency-Key`。读取并编译成功后才原子替换；文件整体错误或 IO 故障保留当前配置，返回可读错误。删除可选文件后重载恢复内置清单。
5. 每个新 run 在启动时固定 resolver。一次重载不会改变在途 run 后续节点的 agent；server 重启恢复以当前本地文件重建 resolver。revision 仅为当前服务进程内的配置版本，重启后重新编号。

## 理由（第一性原理推导）

- Agent 定义是工作区配置，不能成为其他工作区的输入；局部 resolver 将作用域与拥有者保持一致。
- 任务运行参数必须在一次 run 内稳定，否则相同节点恢复和失败定位没有可靠基线。
- 显式重载有命令响应和幂等语义，用户可以确认一次配置变更何时生效。

## 被否方案的否决理由（逐一）

- 全局前缀：保留共享可变表，无法保证已经持有的 driver 不受修改影响。
- 自动 watcher：编辑中间态会改变运行环境，且缺少明确的生效命令。
- 无效别名自动回退：可能执行错误的 agent，违反配置错误 fail-closed 的原则。

## 关键实现注意点

- 保留 `registerAgentsYaml` 函数入口用于配置检查，取消它修改全局模板表的副作用；自定义解析使用 `resolveWithAgentsYaml`。
- YAML 解析错误应隐藏原文片段，避免日志或 HTTP 错误复制凭据。读取异常仅 `ENOENT` 视为可选文件缺失。
- 重载串行处理；清单使用公开字段的投影，重载失败不修改 revision 或有效 resolver。
- 并发同键的重载共享一次操作和响应；首次响应持久化后释放在途映射，失败后允许同键重新提交修复。
- 离线测试必须覆盖同名工作区隔离、内置模板不被污染、无效配置、在途 run 固定配置、删除与重启恢复。
